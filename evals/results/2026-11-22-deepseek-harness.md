## 需要说明的限制

- 每个用例只跑了一次，模型有随机性，24 条也是很小的样本。
- 用例是作者写的，不是盲测。多数正例带有明确线索词，例如"分阶段"、"stages"、任务 ID，场景提示里还直接写了"用 Iteron"，所以测的主要是"被点名后会不会用对"，不是"会不会自己发现该用"。
- 负例 b01 和 b04 在 90 秒时被终止，之后是否才加载 skill 没有观察到。
- 三个场景都是很小的项目，agent 很轻松就做完，区分度不够。全部通过说明这套场景挑不出问题，不说明 skill 没有问题。
- 评分器最初只检查记录，没有检查代码是否修好，是人工核对后才补上这项检查。

## 值得注意的观察

- agent 全程**手写**记录，没有使用 `new-task.mjs`、`add-stage.mjs`、`close-task.mjs`。它只运行了 `check-records.mjs`，每次运行都是 0 error，所以在这些场景里，脚手架脚本没有被采用，也没有看到它们能避免的错误。
- 记录质量不错：没有 git 时用 `sha256` 写 `revision`；重新规划时明确写了"本次不改代码"；发现 `Number.isFinite` 会让空单元格也通过，并在修复里处理了。
- `fresh` 里的 `checked_by` 有的是 `reference data`，有的是 `author`。
